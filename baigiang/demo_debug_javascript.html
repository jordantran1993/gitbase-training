Bóc Mẽ Sự Khác Biệt: console.log() vs DevTools Debugger

Trang web thực nghiệm tương tác giúp Mentor thị phạm sự vượt trội của Breakpoints, Scope, Call Stack và Network tab.

⚡ PHÍM TẮT DEBUG CHROME (F12 mở DevTools):
F8 Tiếp tục chạy (Resume)
F10 Bước qua dòng tiếp (Step Over)
F11 Đi sâu vào trong hàm (Step Into)
Shift+F11 Nhảy ra khỏi hàm (Step Out)
🛒 1. Vòng Lặp 100 Món (Tổng Ra NaN - Không Biết Món Nào Bị Lỗi)
CONDITIONAL BREAKPOINT

Mảng có 100 sản phẩm, kết quả tính tổng ra NaN. Lập trình viên hoàn toàn CHƯA BIẾT món số mấy bị lỗi! (Ta không phải thầy bói để đoán trước id === 77).

❌ Thói quen console.log
Gõ console.log(item) ➔ Xả lũ 100 dòng rác vào Console! Phải cuộn chuột mỏi tay soi từng object để tìm món nào có giá trị dị tật.
✔️ Đỉnh cao DevTools (Bắt theo biểu hiện lỗi)
Chuột phải dòng tính tiền đặt Conditional Breakpoint theo trạng thái lỗi:
typeof item.price !== 'number' || isNaN(item.price)
➔ Trình duyệt tự lướt qua 99 món chuẩn và phanh gấp đúng món gây lỗi! Soi tab Scope mới biết: à, hóa ra là id: 77!
Màn hình kết quả:
Bấm nút để chạy tính toán...
🔍 2. Chiếc Nút Bấm Ẩn Danh Trong 500 File
EVENT BREAKPOINTS

Sếp giao em sửa lỗi nút bấm "Hủy Đơn Hàng". Dự án lớn có 500 file JS, em hoàn toàn không biết hàm xử lý nút này nằm ở file nào, dòng bao nhiêu!

❌ Cách dùng console.log
Bất lực! Không biết hàm nằm ở đâu thì biết gõ console.log() vào chỗ nào? Phải ngồi search text mò mẫm cả buổi sáng.
✔️ Cách dùng DevTools
Mở tab Sources ➔ Bảng bên phải: Event Listener Breakpoints ➔ Mở Mouse ➔ Tích chọn click. Bấm nút là DevTools tự trỏ đến đúng dòng code!
Trạng thái hệ thống:
Đơn hàng #DH-8899: Đang chờ giao dịch...
🐛 3. Bẫy Biến Tham Chiếu (Asynchronous Mutation)
REFERENCE TRAP

Tạo object user = { name: "An", role: "guest" }. In ra bằng console.log(user). 1 giây sau, một tác vụ ngầm sửa user.role = "admin".

❌ Lừa dối của console.log
Khi em bấm mũi tên mở rộng object trên tab Console, em thấy role: "admin" dù lúc log là "guest"! Vì console.log đọc tham chiếu sống trong RAM khi mở rộng.
✔️ Sự thật với Breakpoint
Breakpoint dừng thời gian ngay tại dòng khởi tạo. Bảng Scope hiển thị 100% sự thật bất biến tại khoảnh khắc đó: role: "guest".
Màn hình kết quả:
Bấm nút để kích hoạt... Mở tab Console (F12) để xem điều kỳ lạ!
⚡ 4. Sửa Biến Trong RAM & Replay XHR
NETWORK & RAM MUTATION

Điền form gửi API. Khi có lỗi 400 hoặc muốn thử đổi giảm giá: Không cần reload trang hay điền lại form!

❌ Cách dùng console.log
Gửi lỗi phải F5 tải lại trang ➔ Toàn bộ form bị trắng trơn ➔ Lại phải ngồi gõ lại họ tên, mã giảm giá từng ô từ đầu!
✔️ Tuyệt chiêu DevTools
1. Mở tab Network ➔ Chuột phải request chọn Replay XHR bắn lại ngay trong 0.05s.
2. Cắm breakpoint trong hàm tính toán ➔ Mở Console gõ đè biến trong RAM!

👨‍🏫 HƯỚNG DẪN DÀNH CHO MENTOR KHI THỊ PHẠM TRÊN GOOGLE MEET

  1. Bước 1: Mở trang web này trên Chrome, bấm phím F12 mở sẵn DevTools và share toàn màn hình.
  2. Bước 2 (Thị phạm Kịch bản 1 - Bắt lỗi không cần đoán ID):
    • Cách 1 (console.log): Bấm nút 1, mở Console chỉ cho học viên thấy 100 dòng log ngập lụa, phải cuộn tìm to mắt.
    • Cách 2 (Conditional Breakpoint theo biểu thức lỗi): Mở tab Sources ➔ Mở file demo_debug_javascript.html ➔ Tìm hàm runScenario1_DevTools ➔ Chuột phải dòng totalAmount += item.price; chọn Add conditional breakpoint ➔ Gõ điều kiện bắt lỗi: typeof item.price !== 'number' || isNaN(item.price). Quay lại web bấm nút 2. Trình duyệt lướt qua 99 món chuẩn và phanh gấp đúng món bị lỗi! Lúc này nhìn sang bảng Scope mới vỡ lẽ: id = 77, price = "chưa_cập_nhật"!
    • Cách 3 (Pause on Exceptions): Trong tab Sources, bấm bật icon tròn Pause on exceptions (màu tím/xanh). Bấm nút 3 "Thử Pause on Exceptions" ➔ Trình duyệt tự phanh khựng ngay tại dòng gây crash mà không cần đặt trước bất kỳ breakpoint nào!
  3. Bước 3 (Thị phạm Kịch bản 2): Vào tab Sources ➔ Mở rộng bảng Event Listener Breakpoints ở cột phải ➔ Tích chọn Mouse -> click. Quay lại web bấm nút đỏ "Hủy Đơn Hàng". DevTools tự nhảy vèo đến dòng bắt sự kiện mà không cần đi tìm file!
  4. Bước 4 (Thị phạm Kịch bản 4): Mở tab Network lọc Fetch/XHR. Bấm nút "Tính Tiền & Bắn API". Chuột phải vào dòng request post vừa gửi chọn Replay XHR để học viên thấy request được bắn lại tức thì mà không cần gõ lại form.
